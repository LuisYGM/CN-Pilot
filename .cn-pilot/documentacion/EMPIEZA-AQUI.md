# Empieza aquí

CN Pilot te ayuda a llevar un proyecto describiendo lo que quieres conseguir en lenguaje natural. No necesitas experiencia técnica, prompt engineering ni aprender cómo se organiza internamente.

## Empezar

1. Usa el repositorio como template, clónalo o copia sus archivos a una carpeta de trabajo.
2. Abre la carpeta en VS Code con Kilo Code y completa la configuración inicial siguiendo [esta guía breve](CONFIGURACION-KILO.md). Si Kilo te pide elegir un agente, selecciona **Jefe de proyecto**.
3. Ejecuta `/nuevo-proyecto` para iniciar u orientar el proyecto.
4. Explica tu objetivo con tus propias palabras. Por ejemplo: «Quiero una web para mi clínica» o «Quiero mejorar el proceso de reserva de esta aplicación».

`/nuevo-proyecto` no significa crear una web desde cero. Sirve para proyectos nuevos y existentes, aplicaciones, tiendas, contenido y mantenimiento. Si el contexto ya está preparado, no necesitas repetir el comando: continúa conversando sobre el trabajo actual.

## Una conversación, no un formulario

Jefe de proyecto inspecciona primero el contexto disponible, la implementación y los materiales relevantes. Si algo importante ya está en un brief, una auditoría o los recursos del proyecto, lo reutiliza; no vuelve a preguntarlo. Después pregunta solo por la primera decisión material que aún falte y adapta la conversación a tus respuestas.

Puedes contestar brevemente, decir «no lo sé», posponer una etapa o decir «decide tú». Los detalles no necesarios para el trabajo actual pueden quedar pendientes. No tienes que escoger tecnologías ni seguir una lista fija de fases.

## El proceso se adapta al proyecto

- **Proyecto nuevo o web pública:** se prepara lo necesario para el objetivo actual; las etapas de estrategia, contenido y diseño solo se incorporan si aportan valor o hacen falta para decidir.
- **Aplicación o SaaS:** se priorizan las personas usuarias, los flujos y el comportamiento de la aplicación; no se impone el recorrido de una web de marketing.
- **Proyecto existente:** se identifica qué ya funciona y qué debe conservarse. Un cambio pequeño puede ir directamente a inspección, corrección y prueba.
- **Mantenimiento:** se sigue el problema concreto desde diagnóstico hasta verificación, sin crear documentación o fases que no se necesiten.

Una etapa recomendada no es obligatoria. Si decides dejar el contenido, SEO u otra parte para más adelante, Jefe de proyecto continúa cuando eso no impida hacer bien el trabajo actual. Solo detendrá el proceso ante una decisión humana o autorización realmente necesaria.

## Qué ocurre después

Cuando se resuelve un hito importante, Jefe de proyecto puede resumir qué cambió, dónde está el proyecto y qué recomienda hacer ahora. Si el trabajo siguiente ya estaba incluido en tu solicitud y no requiere una decisión tuya, continúa sin pedirte permiso otra vez.

Las revisiones humanas siguen siendo necesarias cuando hay que escoger una dirección visual, cambiar materialmente el alcance o autorizar una acción externa. Antes de publicar, modificar producción, mover una implementación o realizar una acción difícil de revertir, se explicará el impacto y se pedirá la aprobación correspondiente.

## No hace falta memorizar comandos

Después de iniciar el proyecto puedes pedir trabajo normalmente: «prepara los textos de la página de servicios», «corrige el menú móvil» o «diagnostica este error». Los comandos adicionales son atajos opcionales; no tienes que elegir agentes, skills ni etapas internas.

Para conocer las reglas de conversación, consulta [Interacción human-first](INTERACCION-HUMANA.md). Para ajustes de Kilo, consulta [Configuración de Kilo](CONFIGURACION-KILO.md). No es necesario leer la especificación interna de CN Pilot para usarlo.
