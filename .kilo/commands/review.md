# Review

1. Obtén `git status` y `git diff`.
2. Identifica requisitos/criterios.
3. Delega a `reviewer`.
4. Carga reviews específicas si aplican: seguridad, performance, accessibility, SEO o testing.
5. Clasifica hallazgos.
6. No corrijas automáticamente hallazgos importantes sin devolverlos al Dev Lead.
7. Finaliza con APPROVED, APPROVED WITH NOTES o CHANGES REQUIRED.
