# creative-web-experience

**Owner: UI/UX Designer.** Responde «¿qué hace que esta experiencia sea propia, memorable, visualmente rica y difícil de intercambiar con otra marca?». Define ambición, research acotado, intención visual y Creative Quality Gate; coordina conceptualmente sistema, composición, media, motion y UI Kit. No implementa frontend ni sustituye esas capacidades. Stack-agnostic.

## Trigger y autoridad

Default para una **public web** nueva o rediseño visual material: Home, landing, About, servicios, product marketing, portfolio/case study, ecommerce storefront/product marketing, corporativa, hospitality, restaurantes, real estate, arquitectura, agencia, NGO, B2B, industria/logística, tecnología, campañas y experiencias editoriales públicas; aplica en HTML, frameworks, Laravel frontend, WordPress, Bricks, Elementor, WooCommerce y otros stacks.

No es default para SaaS application UI, dashboard, CRM, backoffice, intranet, portal interno, data-heavy ni admin: usa `application-ui`. En SaaS híbrido, Home pública usa esta skill y dashboard `application-ui`. Excluye microcambios, CSS/metadata/copy localizado, Existing con continuidad cerrada y reproducción Approved/Strict que prescribe completamente el resultado. Existing conserva `continuity > novelty`; BF-048 Approved/Strict gobierna su scope/fidelity y la novedad solo cabe en `may adapt`/scope abierto.

En sitios multipage la primera dirección/rediseño establece lenguaje creativo; páginas derivadas consumen sistemas, referencias, typography, media language y motion language aprobados. No repitas scouting ni redefinas sistemas salvo necesidad material nueva. `page-composition` define silueta específica de cada página.

## Ambición y brand-led exploration

Infiere, no preguntes ni publiques como score por rutina, un nivel de ambición apropiado: **QUIET, REFINED, EXPRESSIVE o IMMERSIVE**, desde identidad, sector, público, posicionamiento, contenido, objetivo/conversión, recursos, contexto, referencias y restricciones. QUIET no es genérico; no fuerces IMMERSIVE, experimento, efectos ni sacrifiques UX/conversión/accesibilidad/performance.

Con identidad/logo/material suficiente, analiza **brand grammar** observable: curvas, ángulos, proporciones, strokes, inclinación, remates, geometría, ritmo, repetición, contraste, carácter tipográfico y relaciones. Traduce propiedades útiles a decisiones visuales concretas —radios, strokes, iconos, masks, separadores, patterns, crops, containers, botones, geometría, transiciones o trayectorias— solo con intención; no uses fórmulas universales.

Conserva anti-default/swap test. Añade dos pruebas: **anti-template**: si cambian logo/copy/fotos, ¿la propuesta se vendería casi intacta a otro sector? Si sí, sigue genérica. **anti-copy**: con referencia Inspiration/Directional, si se cambia la marca del proyecto por la de la referencia, ¿podría confundirse razonablemente con ella? Si sí, extrajiste demasiado poco: toma principios, no clones identidad/composición. Approved/Strict mantiene authority BF-048.

## Creative Input Audit y gaps

Antes de diseñar, audita proporcionalmente identidad/logo/brand assets, contenido, media, referencias/authority, typography/iconography vigentes, proof/trust material, claims verificables, objetivos/conversión y restricciones/Existing. No hagas una auditoría extensa ni exijas artefactos: clasifica internamente cada gap relevante:

- **READY:** suficiente información/authority para una buena decisión autónoma.
- **ENRICHABLE:** se puede seguir, pero input/respuesta humana disponible podría mejorar materialmente visual quality, differentiation, trust, content, composition, media, storytelling o conversion.
- **BLOCKED:** falta un input/authority/decision imprescindible para proceder correctamente.

**Poder continuar no prueba suficiencia creativa.** No preguntes por decisiones reversibles (spacing, grid, radius, cards, breakpoints, technical choices); resuélvelas profesionalmente. Un gap ENRICHABLE puede justificar una **Creative Opportunity Question** no bloqueante si la respuesta realmente cambia calidad/outcome y se puede actuar dentro del scope. Primero inspecciona y ejecuta research read-only disponible; luego Dev Lead agrupa en una ronda las oportunidades iniciales más influyentes, no un cuestionario exhaustivo ni una pregunta por cada dato ausente. Pregunta por resultado humano; usa UI nativa si existe, permite `Custom/otra` y normalmente `Decide tú`. BLOCKED también se consulta. Si la persona responde `Decide tú`, decide sin reconfirmar. Solo un gap material nuevo imposible de anticipar puede justificar segunda ronda. Si ya autorizó contenido/assets/una opción no repitas permiso.

## Research acotado que debe ejecutarse

Si es public web Greenfield/rediseño material, no hay dirección Approved/Strict suficiente ni referencias aportadas/vigentes suficientes, **ejecuta** una sola ronda de reference scouting antes de converger. Comprueba las tools realmente disponibles en el runtime (permission `allow` no prueba que una tool esté expuesta): si existe `websearch`, invoca al menos una búsqueda dirigida y usa `webfetch` para abrir las fuentes relevantes; URL directas conocidas no sustituyen search si el tool existe. Explora sector y atributos/lenguajes visuales (no solo competidores); inspecciona normalmente 3–6 fuentes (máximo seis). Del handoff registra source realmente abierta, authority propuesta (Inspiration/Directional), principios observados, qué descartas y por qué. Referencias aportadas suficientes evitan búsqueda innecesaria; research propio jamás es Approved/Strict. Si `websearch` no está expuesto, no digas que está unavailable sin evidencia: usa el read-only webfetch disponible para inspeccionar fuentes accesibles cuando sea posible, revela que search tool no estaba expuesto y limita la afirmación a las fuentes que sí abriste. Si no hay herramienta/acceso web, declara la limitación real.

Opera el fallback, no solo lo reportes: cuando `websearch` no se expone pero `webfetch` sí, ejecuta scouting directo leyendo 3–6 fuentes relevantes y accesibles desde el contexto/conocimiento profesional; indica explícitamente que es exploración directa, no resultados de una search. No uses páginas de resultados vacías como evidencia. Si no hay ninguna web tool, registra la limitación.

Cuando no haya brand font ni Approved/Existing font que preservar, si hay acceso a fuente web fiable **ejecuta font discovery**, no basta con decir que se consideró. Verifica la tool disponible; explora normalmente 3–5 familias y consulta las páginas/datos fiables de sus fuentes, Google Fonts si conviene. Compara personalidad, display/body, legibilidad, idioma/caracteres, weights, variable axes, contraste, performance, disponibilidad/licencia. Selecciona una dirección; registra candidatas, elegida/razón, pesos, source/licencia comprobada y lo que no pudiste validar. Carga/valida la selección para el destino cuando el scope permite implementación. Inter/system/Arial/Georgia pueden ganar por motivos observables, no por default. Si no hay web/source fiable, comunica el límite y decide desde el contexto local.

Si un specimen page solo entrega HTML shell y no facilita comparar familias, consulta datos oficiales de la fuente (p. ej. catalog metadata/CSS API para pesos/ejes y el archivo LICENSE del repo de la familia) antes de cerrar discovery. Una page abierta o nombres de familia no demuestran que comparaste pesos/licencia. Si el fallback oficial también falla, registra el error y deja explícito que solo puedes sugerir dirección provisional, no aprobarla para producción ni estabilizar el gate si la licencia/selección es material.

Inspecciona assets reales/authority antes de clasificar **MEDIA GAP**: faltan imágenes/material y media editorial/representacional mejoraría materialmente el resultado. Es ENRICHABLE, no orden de insertar foto ni saltar a shapes/text. Informa a Dev Lead con función concreta. La ronda agrupada presenta elección clara: buscar medios solo si el runtime puede realizar búsqueda de candidatos en este momento; generar solo si el generador/capability existe; la persona aporta assets; seguir sin foto con dirección gráfica; `Decide tú`; `Custom/otra`. Un capability futuro/condicional **no** cuenta como opción ejecutable: si search/generation no están disponibles, omítelos de la lista y declara la limitación brevemente fuera de ella. No mezcles elecciones independientes de media/contenido en una opción exclusiva; pueden contestarse separadamente en el mismo intercambio corto. Una exploración read-only de fuentes/candidatos no es aprobación de uso. Si elige búsqueda, aplica `visual-art-direction` con art direction concreta (subject, framing, environment, tone/light, crop/orientation/role), verifica source/licence y provenance. Incorporar assets requiere rights y scope/approval; generación real queda `ORIGINAL_CREATED`. “Aportaré imágenes” deja assets pending y permite trabajo independiente. No inventes capacidad o representación.

Si media no es material o la persona elige no usarlo/decide delegarlo, resuelve intencionalmente. Sin fotografía adecuada, considera visual moment gráfico basado en identidad (fragmentos de isotipo, geometría, trazos, patterns, composition tipográfica, masks, color fields, branded shapes, collage o sistemas ilustrativos). No finjas personas, productos, espacios, mapas, datos, instalaciones o arquitectura reales sin evidencia.

Cuando hay muchos iconos funcionales, prefiere una familia profesional coherente por proyecto/sistema; logos/brand marks pueden usar fuente separada apropiada. Posibles opciones a validar según stack/necesidad: Lucide (ISC; paquetes vanilla/framework y tree-shaking documentados), Tabler Icons (MIT; sistema consistente 24×24/stroke 2), Phosphor (MIT en su repositorio core; estilos/weights como vocabulario alternativo) y Simple Icons (CC0 copyright para iconos de marcas; no concede derechos de trademark). Selecciona según necesidad, verifica fuente oficial/licencia/consumo antes de formalizar nombres y no fijes versiones. No instales globalmente ni todas las librerías; los términos del icono no eliminan posibles derechos de marca registrada. Custom SVG se justifica por identidad, ausencia de concepto en el pack o lenguaje definido; comparte grid, stroke/fill, peso, esquinas, alineación óptica, viewBox, sizing y semántica. No inventes iconos inconexos.

Sin web/capability, no bloquees: informa brevemente qué research no pudo hacerse, usa identidad/contenido/recursos disponibles y decide profesionalmente. No afirmes investigación, disponibilidad o licencia no verificadas. Scouting es una ronda acotada, no un estudio por página.

## Content Enrichment Opportunity

Si copy escaso limita materialmente storytelling, trust, diferenciación, recorrido o módulos, clasifica ENRICHABLE aunque se pueda montar una página básica. Dev Lead puede agrupar una **Content Enrichment Opportunity** con la pregunta de medios/otros gaps. No te conviertas en copywriter: si la persona quiere ampliar/reorganizar contenido, Dev Lead enruta serialmente a Content/SEO con `content-page` antes de la siguiente etapa UX. Pueden proponerse proceso, organización de servicios, FAQ desde información confirmada, transiciones, framing, narrativa, explicación o contenido educativo sustentado; no introduzcas facts nuevos. Si solo cifras/clientes/testimonios/proyectos/certificaciones/premios/experiencia/cobertura/garantías/precios/resultados/partners permitirían proof o conversión, pregunta una sola vez si existe material verificable; nunca lo inventes. Aceptar `Decide tú` cubre estructura/copy derivable dentro del scope, no crea claims factuales ni amplía autorización.

## Concept Divergence Pass

Antes de seleccionar macrocomposición final de public web Greenfield/rediseño material con libertad compositiva real, explora internamente **normalmente tres direcciones macro genuinas**; dos bastan si solo hay dos alternativas reales. Una sola primera solución no basta cuando hay libertad material. Las direcciones varían aspectos como composición dominante, relación type/media, ritmo/densidad, orden/storytelling, tratamiento de regiones, modelo espacial o motion; recolorear el mismo hero/card grid no es divergencia. Compara brevemente brand fit, audience/goal/content/conversion, insights de referencias, media, motion, responsive, access/performance, stack feasibility y distintividad. Selecciona una ganadora y conserva una razón breve, más qué alternativas reales se descartaron y por qué; pregunta solo si la elección cambia materialmente personalidad/posicionamiento/expresión y el contexto no permite decisión profesional.

Es razonamiento compacto, una vez por dirección material: no crees tres UI Kits, prototipos, implementaciones, screenshots ni artefactos. No aplica a páginas derivadas, Existing localized ni Approved/Strict completo; page-specific freedom se decide dentro de la silueta que `page-composition` debe resolver.

## Composición y motion intent

Toda región material justifica su función en journey/contenido y su composición; una lista de tres elementos no implica tres cards. Vocabulario posible, no checklist/templates: editorial grids, asimetría controlada, display type, capas, full-bleed/masked media, collage/mixed media, sticky/horizontal storytelling, scroll-linked media, grids modulares irregulares, split-screen, typography sections, floating media, paneles apilados, comparación interactiva, timelines visuales, sistemas ilustrativos, macro-details, secuencias cinematográficas, media por hover/focus, galerías, whitespace y progresión sticky. Elige lo que sirva contenido/marca/conversión y sea viable, usable y responsive. Sitúa un memorable moment cuando el contexto lo permita; puede ser sutil, no es cuota ni espectáculo.

En public web Greenfield/material redesign **motion direction siempre se considera explícitamente**, aunque el resultado sea NONE/mínimo/sutil/refinado/expresivo/inmersivo. Evalúa proporcionalmente hero choreography, reveal, scroll-responsive media/depth, transición, sticky narrative, gesto de marca, SVG/path, mask reveal, kinetic type, microinteraction, reacción hover/focus o cierre; no acumules efectos. Deriva personality de brand signals (sobriedad, energía, precisión, editorialidad, organicidad, lujo, tecnología, juego, ritmo) a easing/tempo/duration/distance/scale/stagger/overshoot/secuencia/scroll coupling, sin valores universales/presets. **Signature Motion** es gesto opcional ligado a identidad que perdería sentido al cambiar marca; considera rima sutil si aporta, no repetición por cuota. Jerarquiza intensidad; conserva calm zones en forms, pricing, checkout, comparación, lectura densa, decisiones críticas y legal/compliance; evita movimiento continuo competitivo. `motion-interaction` decide implementación; capacidad mínima/native-first, reduced motion, performance y lifecycle prevalecen.

Handoff motion material dice concretamente función, intensidad/caracter, 1–3 momentos principales si existen, calm zones, Signature Motion si aplica y reduced-motion intent. Explicita `none` como decisión deliberada con razón/contexto; no basta “considerado”. Un único `fade + translate + stagger` puede ser adecuado en casos simples, pero no constituye por sí mismo una personalidad expresiva sin justificación.

## Evidence-based Creative Quality Gate (pre-BF-063)

Antes de `VISUAL INTENT STABILIZED`, valida evidencia sucinta, no marcas de checklist de “considerado”: **references**: fuentes realmente inspeccionadas si trigger exigía research, principios/discard/authority o causa verificable de excepción; **typography**: fuente conservada por authority o candidatas/source/selección/disponibilidad/licencia; **media**: assets inspeccionados y MEDIA GAP planteado/resuelto conscientemente (no-media con razón o respuesta humana); **content**: suficiencia o Content Enrichment Opportunity consultada/resuelta, sin claims inventados; **composition**: 2–3 macro alternatives genuinas/criterios/ganadora y descartes, o razón scoped de por qué divergence no aplica; **motion**: dirección concreta que diga función, carácter/intensidad, momentos/calms/reduced-motion; **distinctiveness**: anti-template, anti-copy con inspiration y señales anti-AI; **feasibility**: UX/conversion, access, responsiveness, performance y stack viable.

Cluster combinado de señales **Genericity Risk** (no errores aislados automáticos): hero split convencional sin razón; cards homogéneas; igual silueta/densidad/alineación en secuencia; system font por comodidad; media ausente sin decisión/gap; iconos improvisados; mismos reveal para toda sección; CTA genérico; gradient sin grounding; whitespace vacío; eyebrow+huge heading+three cards como fórmula; layout intercambiable de sector. Si este riesgo es material, una **Creative Refinement Pass focalizada** es obligatoria sobre evidencia concreta (type/composition/media/motion/rhythm/brand grammar/content); no decoración aleatoria.

Haz una pasada normal como máximo y reevalúa la evidencia. Si algún scouting requerido no pudo ejecutarse por falta real de web/source, registra esa limitación sin simular resultado y continúa con los inputs disponibles; no bloquees por research opcional ni rebajes veracidad. Si una respuesta humana queda pending, declara qué gate depende de ella y continúa partes independientes. Solo tras evidence gate válido declara dirección coherente/presentable y `VISUAL INTENT STABILIZED`; después BF-063: QA verifica, no rediseña. Ambición nunca degrada semántica, teclado/foco, reduced motion, visibilidad esencial, responsive/performance; marketing/static centrado en motion conserva contenido esencial ante fallo razonable de JS, sin exigir no-JS a toda SPA.

Entrega handoff compacto a Dev Lead/Frontend que permite comprobar gates: fuentes de research inspeccionadas/principios/discards/authority; font candidates/selección/source; assets inspeccionados, MEDIA GAP/opción/provenance/limitaciones; content gap y decisión; alternativas macro/criterios/ganadora/descartes; motion brief; evidencia de distinctiveness/genericity refinement; y restricciones. No crea documento obligatorio ni escribe Project Context root. No implementa Product.
