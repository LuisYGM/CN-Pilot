# wordpress-plugin

1. Define objetivo y límites.
2. Elige arquitectura proporcional.
3. Usa un bootstrap claro.
4. Separa admin/frontend cuando aporte valor.
5. Carga assets solo donde se necesitan.
6. Usa prefijos/namespaces para evitar colisiones.
7. Valida activación, desactivación y uninstall.
8. No borrar datos en uninstall sin decisión explícita.
9. Considera compatibilidad requerida.
10. Documenta hooks públicos si se pretende extensibilidad.
