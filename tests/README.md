# Tests

La estrategia depende del stack y riesgo.

- DIRECT: verificación mínima suficiente.
- TASK: comportamiento afectado y regresiones.
- STRUCTURAL: criterios de aceptación y riesgos.

Posibles capas: syntax, lint, unit, integration, browser/e2e, smoke, responsive y accessibility.

No añadir un framework de tests solo porque esta carpeta exista.
